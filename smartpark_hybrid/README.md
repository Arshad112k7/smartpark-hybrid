# SmartPark Hybrid Demonstration Starter

A Python FastAPI service and live admin dashboard to present beside the existing Figma driver prototype.

## Included
- FastAPI API and WebSocket event channel
- SQLAlchemy persistence
- SQLite for local setup; PostgreSQL support through `DATABASE_URL`
- 36 parking bays: 12 each on P1/P2/P3
- Consistent starting state per floor: 4 available, 5 occupied, 3 reserved
- Automatic software-generated vehicle arrivals/departures every 15 seconds
- Pause/resume, manual vehicle event and reset controls
- Booking endpoint with PostgreSQL row lock (`SELECT ... FOR UPDATE`)
- Simultaneous booking test; conflicting requests should return HTTP 409
- Recent event feed and live occupancy dashboard

**Simulation disclosure:** this project does not connect to physical CCTV, sensors, gates or vehicles. Vehicle activity is generated by software.

## Run locally (Windows PowerShell)
1. Install Python 3.11 or 3.12.
2. Extract the ZIP and open PowerShell in this folder.
3. Run:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:DATABASE_URL="sqlite:///./smartpark_dev.db"
$env:SIM_INTERVAL_SECONDS="15"
$env:SIMULATION_ENABLED="true"
uvicorn main:app --reload
```

Open `http://127.0.0.1:8000` for the dashboard and `http://127.0.0.1:8000/docs` for API docs.

## Cloud target for 20-user demo
Recommended initial target: one Render Docker web service + Neon managed PostgreSQL. Set `DATABASE_URL` as a Render secret/environment variable using a PostgreSQL URL such as:

`postgresql+psycopg://USER:PASSWORD@HOST/DBNAME?sslmode=require`

Do not commit credentials. Use `render.yaml` as a deployment starting point. Test the health endpoint `/health`, booking conflicts and WebSocket updates after deployment.

## Important deployment note
This initial version runs its simulation task and WebSocket connection manager inside one web process. It is a suitable single-instance demonstration starter, not a horizontally scaled production service. Before running multiple app instances, move scheduled simulation to a dedicated worker and use Redis Pub/Sub (or another broker) for cross-instance WebSocket broadcasts. Add authentication, database migrations, rate limiting and monitoring before production use.

## Figma relationship
Figma Present is a separate click-through prototype and cannot directly call this backend or subscribe to WebSockets. Present the Figma driver prototype on one screen and this live dashboard on another. Use matching scenario steps; link the deployed dashboard URL from Figma when hosting is ready.
